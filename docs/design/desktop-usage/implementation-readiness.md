## 实施阶段的真实数据验证

这项允许适用于开发验证。成品面向用户的首次启用数据源仍遵守界面选择合同，
两者不是重复审批。当前会话后续进入实施时，可直接在下列范围开展验证：

1. M0 从本机已安装、属于 M2–M5 的 Agent 版本与已知候选目录开始有界发现；
   不全盘扫描，不读取 F1 产品数据，不为制造样本启动 Agent 或发起模型调用。
   版本优先从本地包/安装元数据取得，避免调用会隐式初始化或写库的 Agent 入口。
2. 编写并审阅最小的本地字段提取器后取得格式样本，再构造 parser fixture。
   先前“fixture 通过后再真实核对”指解析器/端到端验证，不阻止 M0 为生成 fixture 读取必要样本。
   初始每格式取少量近期会话，覆盖新增、缓存、模型变更或辅助调用；缺失场景用合成样本补充并标识。
3. JSON/JSONL 可在本地进程中解析，向工具输出和文档只返回字段白名单、匿名关联 ID、
   schema/版本、数值及汇总差异；不打印完整记录。SQLite 只读查询必要列，不 SELECT * 或输出对话正文。
   usage 若嵌在消息 JSON 中，可在本地解析所需字段并丢弃正文，不能把整段 JSON 返回工具输出。
   活库一致性、锁冲突和备份条件遵循架构合同，不能因验证而迁移、修复或 checkpoint 源库。
4. 提示词、回答、工具参数/输出、密钥、邮箱、真实项目路径不进入模型上下文、日志、Git 或 CI。
   关联 ID 使用本轮稳定匿名映射；schema 所需的正文占位用常量，保留 token 数字与包含关系。
   真实样本只证明该版本、字段及覆盖范围；没有字段时保留 unknown，不凭文本补计数。
5. 临时验证库和脱敏中间文件放已忽略的 build/desktop-usage-validation/，记录本任务产物清单。
   尽量不复制原始日志；若 SQLite 一致性确需暂存副本，限制当前用户访问，只本地处理并及时清理。
   测试产物与源目录分离，不能修改、删除或清理 Agent 的原始会话。
6. M1–M5 先通过合成/脱敏 fixture，再对相同版本的真实来源做只读核对，比较已知 token、
   缓存、调用单位、时区和范围。记录差异及不完整原因，不为吻合源界面而更改统计合同。
7. 检查脱敏 fixture 后才纳入版本库；CI 只使用已审阅 fixture。报告记录版本、格式、
   匿名来源、样本覆盖、字段能力、差异和命令结果，不附完整私人数据库或绝对个人路径。

源不存在或安全读取失败时记录该源未验证并继续其他来源；不接入远端账单/API 填空。
WSL/容器仅在本机已可访问且归属清楚的范围内读取；需要启动环境、修改配置或产生付费用量时，
按当时实施范围处理，不把本机数据验证许可扩展成任意外部操作许可。
