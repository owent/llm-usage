# 本地 AI 用量桌面客户端设计

本设计于 2026-09-24 编写，尚未实现。当前交付为 [执行计划](../../../Plan.md)及其详细合同。
公开文档、固定版本源码和现有原型的静态检查是决策依据；没有进行真实 Agent 采集或性能测试。
实施前的范围决策与文档准备已完成，见 [开工准备](implementation-readiness.md)；M0–M7 尚未执行。

## 产品目标与边界

让用户看清本机各 Agent、各模型在今天和历史期间的可观测用量，
判断主要消耗来自哪里、缓存使用是否变化、哪些来源尚未完整采集。
仅统计本地数据，无账号登录、云同步或外部数据库要求；统计不需要额外调用大语言模型。

“本机”指当前电脑上的 Agent 运行实例产生的日志、数据库、用量文件及显式启用的本机遥测。
读取本机 Agent 对云端模型的调用记录仍属于本地统计；这不要求模型本身离线运行。
本机 WSL/容器须显式添加，记录发行版/实例身份并去重；不自动扫描或启动其环境。
SSH/远端 Gateway、网络共享、云端账单与企业/跨设备账号报表均不接入；
远端导出下载到本地、远端会话同步到本地或文件来自云同步盘，都不能据此证明本机归属。
本地会话导出须保留可核验的本机来源和原生粒度；无法确认归属的记录不纳入总计，并显示排除原因。
没有数据不是零用量，源日志存在也不代表所有模型请求都被记录。

已确认 Windows 11 x64 首发，GitHub CI 保留 Windows/macOS/Linux 的实际构建与测试任务。
本地可用 WSL 2 尝试 Linux 构建；WSLg 冒烟、CI 编译和真实桌面验收分别记录。
Harness Agent 已确认是 [Hermes Agent](https://hermes-agent.nousresearch.com/)，接入依据见 A24。
用户已允许实施阶段提取本机真实 Agent 数据验证；按最小字段、只读和脱敏流程进行。
JetBrains/TRAE、Zed 内置及其他缺证 IDE 变体保留在 F1 后续支持计划，当前不实施；
有本地字段证据的扩展/遥测继续按原阶段推进，详见接入矩阵。

## 主要决策

| 决策 | 理由 | 尚待验证 |
| --- | --- | --- |
| Tauri 2 + Rust 后端 | 使用系统 WebView；文件与数据库访问集中在本地后端，符合减少自带运行时的目标 | 本项目实际安装包、全进程内存、跨平台行为 |
| SQLite，单写者 + WAL | 本地增量采集需要事务、唯一约束、可更新记录和按条件汇总；无额外数据库服务 | 百万级数据、并发读写、保留清理、损坏恢复 |
| Svelte + TypeScript，ECharts 按需导入 | 页面以筛选、设置与图表为主；延续原型的图表交互，减少组件引入范围 | 与纯 TypeScript 最小试验比较产物和维护成本；不预设性能差值 |
| 全部 Agent 分期尝试本地提取；本地遥测/本机会话导出补充 | 已有本地历史可回填；本地遥测补足未来请求、延迟和错误信息 | 缺证 IDE 后移 F1；每源独立核验版本/字段/生命周期和本机归属，不接入远端用量 API |
| 区分事件、累计值、区间报表和额度 | 避免把会话行数、token 直方图样本数和积分误作请求数 | 所有适配器的字段级 fixture |
| 内置编译型适配器 | 首版不引入任意脚本执行、插件商店或常驻旁路服务 | 新适配器通过正常应用升级分发 |

技术依据及替代方案见 [架构](architecture.md)；来源证据见 [调研记录](research.md)。

## 页面与交互

首版为一个主窗口、四个导航入口：总览、模型与 Agent、数据源、设置。
自动提取可全局或逐源配置，应用运行时默认启用；托盘、开机启动、Windows 系统定时任务默认关闭。
关闭窗口、退出进程、休眠和注销时能否提取在设置页分别说明，详见 [调度合同](scheduling.md)。

| 页面 | 显示内容 | 操作及失败反馈 |
| --- | --- | --- |
| 总览 | 今日 token、已观测模型调用、缓存输入占比、来源新鲜度；所选期间汇总 | 今日/7 天/本周/本月/自选日期；刷新显示逐源进度，失败保留旧数据并标记时间 |
| 趋势 | 按日/周/月的堆叠柱图；今日按小时趋势 | 模型/Agent 切换，点击图例过滤；当前未结束周期用虚线或浅色表示 |
| 模型与 Agent | 模型排名、输入/输出/缓存拆分、交叉表、可选供应商及项目 | 同名模型可按供应商拆开；排序、Top N + 其他、导出当前筛选 |
| 详情抽屉 | 用量记录的时间、模型、来源、类别、精度、错误及延迟 | 跳转来源设置；不显示提示词、回答和工具输出 |
| 数据源 | 发现/启用状态、版本、本机归属、字段支持、最近/下次提取、错误摘要 | 添加本地目录/本机会话导出、逐源定时、立即提取、暂停、重扫、移除；显示受限原因 |
| 设置 | 保留、定时提取、后台运行、时区、周起始日、统计维度、模型别名、预算、外观 | 预览下次执行与配置影响；Windows 系统任务显式开启/关闭，失败显示实际生效状态 |

“直观图表”具体包括：token 类型堆叠柱、模型/Agent 横向排行、缓存占比折线、
今日小时图及活动日历热力图。费用、错误率和延迟图按来源能力启用。
同一图避免把 request 和 token 放在相同数轴；比例不能与数量堆叠。
图表必须同时提供可读表格，支持键盘、深浅主题、色觉友好配色及明确单位。
本轮不生成装饰性图片或可运行 UI；界面验收在 M6 完成。

示意布局用于说明信息层级，不表示已有实现：

```text
[总览] [模型与 Agent] [数据源] [设置]     [时间范围] [刷新今日]
已知 token | 已观测模型调用 | 缓存输入占比 | 数据更新时间/缺口
趋势图：日 / 周 / 月                    模型 / Agent 排行
今日小时图                             来源状态与覆盖范围
明细表：模型 / Agent / 供应商 / 已启用维度 / 已知字段
```

## 建议增加的统计

| 内容 | 用户价值 | 数据条件与限制 | 阶段 |
| --- | --- | --- | --- |
| 缓存读取/创建拆分及加权命中率 | 定位高输入消耗和缓存复用变化 | 缓存创建计入总输入；未知字段不补零 | 首版 |
| 单次调用 token 均值、P50/P95、异常大请求 | 识别大上下文、少量高消耗调用 | 只用逐请求完整数据；不混入会话累计记录 | 首版，按能力 |
| 项目/工作区、主调用/子 Agent/辅助调用占比 | 识别标题生成、压缩和后台工作的消耗 | 项目维度默认关闭；父级汇总和子级事件不可双计 | 首版，按能力 |
| 重试、错误、取消及错误请求的已知 token | 解释消耗增长和服务稳定性 | 需要请求生命周期或遥测；日志只记录成功时不显示“成功率 100%” | M5 |
| TTFT、请求时长 P50/P95、输出速度 | 了解交互等待和服务变化 | TTFT 要有首 token 时间；速度用对应生成时段，不能从文件时间推断 | M5 |
| 估算费用、记录费用、本机可归属的积分消耗 | 管理消耗；比较模型与缓存成本 | 仅使用本地字段；价目有版本/币种/生效时间，订阅不能套 API 单价称实际账单 | M6 |
| 同期对比、预算提醒、趋势异常 | 发现持续增加或某日激增 | 今天对比昨日相同已过时段；零基数不计算百分比；数据不全时附说明 | M6 |
| 采集新鲜度、解析失败、字段完整性 | 让总计可解释、可核查 | 只表示已发现来源/已观测记录的覆盖，不能估计未被记录的调用总数 | 首版 |
| 会话数、活跃天数和用量热力图 | 回看使用习惯 | 独立会话做 DISTINCT；活跃日期不等于工作时长或生产力 | 首版 |

不从 token 推导代码质量、节省工时、个人绩效或模型能力排名。
碳排放、GPU 时间和真实缓存内部命中概率缺乏必要数据，暂不设计为产品指标。
“命中率”默认名称为“缓存输入占比”，详见 [统计公式](data-contract.md#metrics)。
