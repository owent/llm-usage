## M0：固定实施边界和试验基线

输入：本文、需求、真实目标平台、允许读取的源范围。

1. 按已确认的 Windows 11 x64 首发与 [三平台 CI](platform-ci.md) 固定 OS/WebView/架构基线。
   Hermes 产品身份已确认，不再作为待决输入；其版本/schema 与其他工具一起核验。
2. 核验仓库实际状态；根 package.json/package-lock.json 当前缺失，已有 node_modules 不构成可复现依赖。
   恢复文档工具声明，建立新应用的独立依赖与锁文件；不要混淆根文档工具和业务运行时。
3. 固定 Rust、Tauri、SQLite、前端、图表及安装工具的实际版本与许可证。
4. 做包含一个图表、SQLite 查询、一个文件读取器的最小 release 试验，记录安装体积及全进程资源。
   与纯 TypeScript 前端做有界比较；只有未达预算或存在平台阻塞才扩展桌面框架比较。
5. 记录 M2–M5 目标 Agent 的本机版本，按已获允许的只读范围提取必要用量字段并脱敏形成 fixture；
   先有人工可核算期望值，再写解析器。F1 的 IDE 本阶段不探测/开发，不要求取得其样本。
6. 建立真实命令与验证记录模板；性能机器、数据分布、依赖版本和退出码可复核。
7. 建立 Windows/macOS/Linux 实际 CI 构建矩阵、fixture 测试和制品记录；发布与 PR 权限分离。
   本地按 platform-ci.md 尝试 WSL 2 Linux 构建，环境缺失如实记录，不阻塞三平台原生 CI。

交付：版本锁定、样本清单、首次资源报告、开发/测试命令、三平台 CI 与 WSL 独立证据。
通过条件：没有未标记的版本假设；关键包体成本可测；缺证工具保留状态但不拖住独立核心。

## M1：统计核心和 SQLite

1. 建立领域类型和 [数据合同](data-contract.md)的人工期望测试。
2. 实现来源实例、标准化事件、累计/区间记录、去重别名与迁移。
3. 实现事件/游标/解析上下文/日汇总的原子提交，故障注入验证恢复。
4. 实现按模型/Agent/provider/日的查询，周/月由日派生；字段完整性随结果返回。
5. 实现更新与撤销旧贡献、数据修订号、查询一致视图、schema 拒绝和恢复。
6. 实现容量统计、保留截止、封存日替换和导入批次身份，禁止过期重扫复活。
7. 保存本机归属依据及排除原因；建立任务规则/状态和统一采集作业合同，供 M6 调度。

交付：核心库、迁移、固定 fixtures 与测试、查询合同及性能初值。
通过条件：V01–V06、V09–V16 对应核心用例通过；不存在“未知=零”或重复扫描增长。

## M1a：历史来源身份与存储分区

依赖 M1，在 M6 数据导出前完成；M2–M5 写入接口按此合同衔接。
现有来源实例不能代替独立主机身份，跨来源日汇总也不能作为未来 Merge 的唯一持久化结果。

1. 按 [来源身份合同](data-contract.md#provenance) 保存稳定主机 ID、主机名及来源实例，
   区分原始来源与本次采集/导入位置；身份不随重启、主机改名或已确认的目录迁移变化。
2. 将来源纳入事件唯一约束、原生汇总和日/封存汇总分区，建立来源/时间查询索引；
   查询可跨来源求和，落盘仍能识别每个来源的贡献，删除明细后也不丢失来源身份。
3. 为已有数据库设计版本化迁移：可证明来源的历史保留关联，无法恢复的来源标为未知；
   不能把混合汇总全归给当前主机或凭空拆分。迁移中断回滚，继续遵守 M1 的一致备份合同。
4. 定义供后续导入/导出/Merge 使用的版本化交换合同：原始来源、记录/分区键、时间范围、
   字段完整性、修订及完整快照/增量性质；明确重复跳过、同源修订替换、互斥来源新增及冲突保留。
5. 补全 V28 的身份、真实 SQLite 迁移和封存汇总回归测试；交换格式与合并判定使用脱敏固定样本。

交付：来源字段与索引、迁移、持久化/查询合同、交换格式及测试。
通过条件：主机改名不重复计数，同名不同主机不发生键冲突；来源未知不被误替换，历史分区可追溯。
完整导入/Merge 功能另行排期；本阶段不扩展当前本机采集边界，也不将主机名作为本机归属证明。

### 适配器目录迁移与版本组织

本项已于 2026-09-25 执行完毕（[m2d 验证记录](../../validation/desktop-usage/m2d-layout-versions.md)；
六源目录结构、注册表分派、兼容标记持久化与回归均通过）。按 [架构合同](architecture.md#adapter-layout)，
所有 Agent 使用独立目录，后续新适配器从目录结构开始；M3–M5/F1 沿用同一要求。

1. 盘点已有 `codex.rs`、`claude.rs`、`pi.rs`、`gemini.rs`、`qwen.rs` 及其测试/调用方，
   迁入各自 Agent 目录；保留中断任务的半成品与原验收状态，移动文件不算适配器验收完成。
2. 在 Agent 目录内拆分统一入口、版本探测/分派及 `versions/` 格式实现；
   产品特有字段映射一并归入对应目录，跨 Agent 仅共享已验证的框架、读取器和辅助逻辑。
3. 明确发布版本到格式实现的映射，当前和历史实现并存；同一目录的新旧文件逐个探测，
   已知版本按映射分派；未知或缺失版本默认尝试该 Agent 对应输入类型的最新内置解析器。
   按 [兼容合同](architecture.md#unknown-version) 校验结构与计量语义，成功结果带兼容标记入库统计，
   不因缺少版本样本直接拒绝；不兼容时保留旧结果。目录迁移与兼容行为调整分别回归。
4. 保持公开入口、来源/记录身份、增量游标及解析上下文兼容，核对 examples、测试和文档引用；
   若确需状态迁移，单独提供版本与恢复测试，不把重构当作清空游标或重建来源的理由。
5. 执行 V17/V30 的结构检查与迁移前后回归；将现有“未知版本一律拒绝”测试改为
   未知版本兼容成功、真实结构破坏失败、部分可用及失败恢复等场景；补齐分派依据和兼容标记的持久化/展示。
   同步探测、扫描和能力声明，避免探测已允许回退、扫描仍按版本白名单拒绝。
   新增历史版本时补分派和混合版本 fixtures，
   修改 Agent 内部共用逻辑时回归其全部已支持版本，修改跨 Agent 共用逻辑时回归全部实际使用者。

交付：按 Agent 分目录的实现、明确的版本映射、迁移回归和后续版本样本组织方式。
只有一个已证实版本时仍交付独立目录；逐版本已验证支持须有实际样本，兼容尝试结果单独标注。

### 逐适配器交付

每个适配器独立交付发现、探测、增量、映射、能力说明及 fixtures。
已验证版本保留专属映射，未知版本先用最新内置解析器尝试；仅解析失败或无法确认的部分显示受限。
兼容尝试不放宽本机来源、字段含义及未知不补零的合同。
原型的环境覆盖与手工根目录配置按平台改成路径列表，不沿用跨平台分号拼接假设。
记录数据源自身保留/关闭持久化时的缺口；源历史不足 366 天不等于应用保留配置失效。

通过条件：V07–V12、V17、V30 对应场景；每个适配器有静态/fixture/真实应用三种证据分列。
解析器 fixtures 通过后对本机真实数据做只读核对；所需允许已给出，不自动发起模型请求。
M0 的最小样本提取先于此门槛，用于生成 fixture，不等于对未验证解析器开放全量采集。

## M4：新版及缺证产品核验

新版 Kimi Code 为用户明确要求的优先项：先核验当前发行版的 wire schema、
稳定调用 ID、模型来源和时间单位，再实现，与旧 Python 格式分开。
Kimi Work、ZCode 的原型解析仅作为定位线索；WorkBuddy 独立保留本地核验记录。
JetBrains/TRAE、Zed 内置及缺证 IDE 变体后移 F1，不在本阶段探测或实施。

交付只能是以下之一：

1. 有证据的本地适配器，附受支持版本及回归样本。
2. 仅本机来源可核验的会话导出/本地遥测接入，明确缺少字段及历史限制。
3. 具体待证项及下一步，界面显示“尚无可靠用量源”，不伪造数值。

找不到入口并不证明技术上不可能；也不无限期逆向私有接口。
每个工具必须保留产品身份、已查官方入口、失败原因及可恢复工作的条件。
本阶段工具安排本地提取尝试，未取得版本/样本时记未执行；F1 留待后续阶段，
不能用云端 API 替代，也不因后移从总矩阵删除产品。

## M5：本机遥测和本地导入

先完成 Copilot/VS Code 的文件导出，再增加按需启用的本地 OTLP 接收器及 CodeBuddy。
显式支持实际发送协议，覆盖 protobuf/JSON 差异、认证、压缩体上限、未知字段和重传。
采用字段白名单，拒绝正文持久化；配置向导只提出本地最小采集设置。

所有来源增加本机归属检查：只接受已启用本机实例的遥测或本机会话导出；
拒绝远端转发、账号/组织汇总，即使文件在本地或数据经 loopback 到达。
JetBrains/TRAE 本地存储核验归入后续 F1；不实现企业 API、账号登录或远端账单导入。
本地同一来源/日期重新导出按修订替换，批次取消/失败保留旧结果，不重复增加。
替换范围由 M1a 的原始来源与完整分区决定，不能仅凭主机名或导入批次 ID 替换历史。

通过条件：V08/V12/V17/V22/V25；进程未运行的采集空白、源端写入延迟、
隐私开关、父子 span、双 instrument token 样本计数均能正确解释。

## F2：模型 API 按量价格获取调研

后续调研，未排期，不阻塞首版；目标是用本地已观测 token 估算对应 API 按量费用。
本任务先交付证据和方案，价格获取、费用计算及 UI 实施在调研后拆分排期。

1. 比较官方价格接口/机器可读数据、官方定价页面、第三方价格目录及手工维护方式。
   核验实际可用性、覆盖、授权与维护成本、更新频率、历史价格和失效行为；
   第三方数据须与官方依据核对，记录来源 URL、检索日期、样本版本和缺口，不预定渠道。
2. 明确供应商、模型原始 ID/版本/别名、地区/渠道、服务档位、批处理、长上下文阶梯、币种及单位。
   分别核验普通输入、缓存读写/TTL、输出与推理的计费关系；不能从模型同名推断同价。
3. 设计本地价格快照、生效区间、更新校验、离线缓存、手动覆盖及失败回退。
   保留价格出处和版本；历史估算可复现，按当前价格模拟须与按发生时价格估算分开。
4. 按 [费用合同](data-contract.md#pricing) 明确缺失 token/价格、部分可计价金额、
   多币种、精度与舍入规则；本地订阅用量套用 API 价格时标明参考估算，不能称实际账单。
5. 明确获取公开价格元数据的网络边界：不上传用量、主机/来源身份、会话或账户密钥；
   不接入远端用量/账单 API。后续价格刷新可配置，失败不影响离线统计。
6. 设计 V29 的固定价格样本、人工期望金额和异常场景，列出费用引擎、价格更新及界面的后续任务。

交付：可核验的渠道比较、选择依据与限制、版本化价格合同、验收样本设计及实施清单。
通过条件：能解释每个拟支持价格的来源、适用条件和更新方式；缺证模型保留未计价，
不把调研完成记为已经获取实时价格或已经通过费用计算测试。

## F3：界面多语言（i18n）方案调研与设计

后续调研，未排期；完成时点约束：在 M6 界面实现开始前完成方案与合同设计，
避免先硬编码文案再返工。调研不阻塞 M0–M5，也不改变首发 Windows 11 边界。
本任务先交付证据和合同，语言包编写与切换的实际实施随 M6 执行。

1. 比较 Svelte/Tauri 生态的 i18n 方案（消息目录、编译期/运行期键解析、
   类型安全键、语言包分包与按需加载），核验实际维护状态、对本项目
   [资源目标](architecture.md#budgets)（前端 gzip ≤ 1 MiB、首屏 P95 ≤ 2 秒）的影响；
   记录来源 URL、检索日期与版本，不预定结论。
2. 确定语言集合与默认语言、语言协商顺序（用户选择 → 系统语言 → 默认）、
   缺失键回退规则；语言切换是即时生效还是需重启须有明确结论与证据。
3. 明确本地化范围：界面文案、图表标签、错误提示、设置项；数字/日期/时区/
   百分比/单位随语言地区的格式化口径（界面展示与导出 CSV 的格式分列）。
   统计口径本身不随语言隐式改变：时区、周起始仍是用户设置，翻译不得
   改变区间、去重或单位含义。
4. 设计键名规范与语言包组织（页面/组件命名空间、插值、复数、日期区间）；
   诊断 code 保持稳定英文标识，诊断 message 的语言策略（展示层映射本地化
   或保持原样）需明确理由；后端 Rust 侧用户可见消息的边界一并界定。
5. 来源能力声明（capability/limitations 等中文文本）的展示语言策略：
   数据源描述不因界面语言改变含义，翻译缺失不得虚构字段能力或覆盖范围。
6. 交付：方案对比证据、选定方案与限制、键名/语言包合同、语言切换行为定义
   及 V31 验收要点。

通过条件：能解释每个拟支持语言的来源、覆盖范围与回退行为；方案对包体/首屏
目标的影响有可核验数字或明确的测量计划；不把调研完成记为已支持多语言，
也不因多语言需求推迟既有验收。

## 变更与回退

每阶段保持可独立审阅的变更；不自动提交、推送或部署。
解析器失效先禁用该源并保留旧结果，可回退到已验证版本；不回滚 Agent 的安装。
数据库迁移失败恢复一致备份；新库版本不能强行用旧程序写。
误清理只可从用户保有的合法备份或来源恢复，界面必须在清理前说明不可逆部分。

阶段完成记录须包括命令、cwd、OS/运行时、锁定版本、退出码、测试数量、
实际结果、失败及未执行项。记录放未来的 docs/validation/desktop-usage/ 下；
只有产生实际证据后才创建记录文件，不预填“通过”。
