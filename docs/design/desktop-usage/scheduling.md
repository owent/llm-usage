# 本地定时提取与后台生命周期

状态：待实现。用户已确定所有 Agent 均尝试本地提取，允许在界面配置自动任务。
本轮只编写合同，不注册系统任务、不启动 WSL/Agent、不读取个人用量。

## 任务与设置

每个已启用数据源都使用同一个采集作业入口；手动刷新、定时器、文件监听、启动和恢复校对
仅是触发原因。任务读取已有本地记录，不执行用户 shell、Agent CLI、定时提示词或模型请求。
无法提取的 Agent 也显示能力和原因；重复定时运行不会让缺少的字段变成可用。

| 设置 | 默认 | 合同 |
| --- | --- | --- |
| 应用内自动提取 | 启用；前台 60 秒、后台 5 分钟 | 仅作用于已启用源；全局可关闭，逐源可继承/覆盖/暂停 |
| 逐源频率 | 继承全局 | 固定间隔 15 秒–24 小时，或每日/每周指定时间；首版不开放任意 cron/shell |
| 定点任务时区 | 首次沿用统计时区并保存 | IANA 时区；后续独立可改，预览接下来 3 次执行；改统计时区不隐式改任务 |
| 文件变更触发 | 间隔模式启用，防抖 2 秒 | 定点模式默认关闭，可单独开启；依赖该源自动提取已开启，暂停后不旁路执行 |
| 启动/休眠恢复校对 | 启用 | 仅自动提取已开启的源；合并错过的时点，每源补扫一次 |
| 托盘运行/开机启动 | 关闭 | 关闭窗口默认退出；选择托盘后才留进程，开机启动单独启用 |
| Windows 退出后定时提取 | 关闭 | 用户界面显式启用系统任务；最短有效调度间隔 1 分钟，精度限制可见 |
| 电池节能暂停 | 关闭 | 开启后暂停自动任务，手动提取仍可用；休眠不唤醒机器 |

设置页展示规则、实际生效模式、暂停原因、最近开始/成功、下次执行、耗时、增改条数和错误摘要。
保存先校验路径、时区、频率及平台能力；按钮提供“立即提取”“暂停”“恢复”“恢复默认”。
任务目标只引用已启用的 source ID；禁用源立即取消后续调度，不允许任务重新启用来源。
未启用应用内自动提取时，手动刷新仍可使用；显示新鲜度时说明对应任务已暂停。

## 调度、并发与恢复

1. 全局/逐源规则持久化为带版本的配置。记录 task ID、来源集合、触发类型、规则/时区、
   启用状态、下次计划时间和最近结果；诊断遵守既有保留上限，不保存日志正文。
2. 进程内间隔等待使用单调时钟；展示时间及定点日历使用 UTC/IANA。
   重启和时钟跳变后重新计算到期规则，不能因回拨而重复执行同一时点。
3. DST 不存在的定点顺延到该计划时点之后首个有效时刻；重复时刻只执行第一次。
   任务身份包含配置版本和逻辑日历时点；错过多次合并为一次校对，不排队回放每个时点。
4. 同源最多一个运行作业和一个合并的待处理触发；不同来源默认并行 2 个，数据库单写者。
   手动/监听/定时重叠共用 job ID 或返回合并状态；完成后若仍有变更才继续下一轮。
5. 每批事件、游标、解析状态、聚合及作业提交进度同事务；暂停/取消在批次边界结束，
   已提交数据保留，未提交数据不推进游标。任务调度成功不等于采集成功。
6. 临时 busy/文件仍在写时最多重试 3 次，退避 5/15/30 秒；未知版本先按
   [兼容策略](architecture.md#unknown-version) 尝试最新内置解析器，不直接跳过采集。
   确认不兼容或权限拒绝后不在同轮循环重试；解析器更新、来源变化或显式重扫可重新尝试。
   初值随 M0 fixture 校准；错误源隔离，慢源不拖住其他来源。
7. 单源每轮默认 30 秒，包含读取与重试等待，先到时间上限就延期，不保证用满 3 次重试。
   整个无人值守进程默认最长 5 分钟；大回填按批次续跑，保留游标。
   任务运行中进程退出后，下次将其标为 interrupted 并幂等恢复；不靠 PID 文件无限占锁。

定时扫描只能观察已落盘的数据，不能恢复上游清掉的历史或尚未写出的 usage。
累计数据两次观察跨日时仍保留区间不确定性，不能把增量全算在唤醒后的日期。
前台 65 秒新鲜度目标仅适用于默认 60 秒规则、源已落盘且正常运行的环境。

## Windows 系统定时任务

选择 Windows Task Scheduler 执行同一应用的拟定 `--collect-due --headless` 模式。
该参数尚未实现；headless 在创建 Tauri 窗口/WebView 之前进入 Rust 采集路径，执行后退出。
没有常驻 Python/Node 服务，也不需要为了定时提取打开窗口。

- 界面生成一项当前用户专属任务：当前用户已登录、普通权限、无需保存密码，默认不唤醒电脑。
  使用 TASK_LOGON_INTERACTIVE_TOKEN 与 TASK_RUNLEVEL_LUA；不采用保存密码或 SYSTEM 身份。
  注销、关机或休眠期间不承诺执行；恢复后下次调度或应用启动补扫一次。
- 操作使用系统任务 API，程序绝对路径与参数分开传递；路径含空格/中文也必须正确。
  不拼接 shell；不创建管理员/SYSTEM 任务；安装位置变化时更新本应用拥有的任务。
- 系统任务按分钟级检查到期规则；所有具体来源与频率仍由应用配置决定。
  小于 1 分钟的规则在仅系统任务模式下显示受限，不声称达到前台刷新精度。
- GUI、托盘与 headless 争用同一个按用户/应用数据目录隔离的跨进程所有权锁。
  已有 GUI 持有时，headless 返回明确的 already-running 状态，由 GUI 调度已持久化规则；
  不并发创建第二个数据库写者。异常退出由 OS 释放锁，重启核对未完成作业。
- 用户选择关闭自动提取时同时关闭系统触发；只退出 UI 时保留用户已启用的系统任务并明确提示。
  保存采用 desired/applied 状态及幂等对账：注册失败、路径失效或禁用失败显示待修复，不能假报成功。
  即使系统任务删除失败，headless 也读取已关闭配置后退出，不继续采集。
- 卸载/关闭功能只移除本应用登记的任务，不改其他任务。升级、单实例冲突、取消和磁盘满需验收。
  任务模式不启动临时 OTLP 接收器，文件提取与实时遥测采集窗口分别显示。

Windows 机制依据：[Task Scheduler](https://learn.microsoft.com/en-us/windows/win32/taskschd/task-scheduler-start-page)、
[执行身份](https://learn.microsoft.com/en-us/windows/win32/taskschd/security-contexts-for-running-tasks)、
[错过时点处理](https://learn.microsoft.com/en-us/windows/win32/taskschd/tasksettings-startwhenavailable)、
[重复间隔](https://learn.microsoft.com/en-us/windows/win32/taskschd/repetitionpattern-interval)。
具体设置和普通用户可用性在 M6 验证，不把 OS 自动补跑语义当作应用幂等保证。
StartWhenAvailable 可能延迟启动，不能据此承诺唤醒后立即提取；实际下次执行状态须反馈给用户。

## macOS/Linux 与本地环境

macOS/Linux CI 必须构建和测试共享调度器、headless 模式、文件读取和数据库互斥。
应用运行期间使用相同定时合同；首版不内置 launchd/systemd/cron 注册界面，平台能力明确显示。
Windows WSL 是本机来源之一时，须用户显式添加；任务不会为读取而隐式启动发行版或容器。
活跃 WSL SQLite 不能通过跨环境共享路径复制三件套；无法保证一致只读时使用本机产生的一致导出，
或保持受限。WSL Linux 应用自己的库放其 Linux 本地文件系统，不与 Windows 应用并发共享库。

验收见 V23/V24/V25；资源测量同时覆盖 GUI/托盘常驻与 headless 每次启动成本。
