# 界面多语言（i18n）方案调研与设计

状态：2026-09-25 完成初版调研；2026-09-27 已扩展为 10 种界面语言，
完整目录与验证见[本轮记录](../../validation/desktop-usage/review-2026-09-27.md#逐日热力图与多语言扩展)。
早期“仅中英双语”的选型推演保留在下文作为历史调研，当前实施合同以
[本项目 i18n 合同](#contract)为准。原生 GUI 验收仍随桌面逐操作验收。
资源与首屏目标见
[架构合同](architecture.md#budgets)（前端 gzip ≤ 1 MiB、首屏 P95 ≤ 2 秒）。

当前前端基线（desktop/package.json）：svelte 5.57.1、vite 8.3.0、
@tauri-apps/api 2.11.1、echarts 6.1.0、typescript 5.9.3。
调研时 src/ 仅有 M0 探针骨架、无文案，故不存在迁移成本；M6 先落地
zh-CN/en，现有 10 种语言均覆盖 292 个界面键。zh-CN/en 基础目录在
src/lib/i18n.svelte.ts，新增语言共享有序键目录在 src/lib/locales.ts。

### 各方案要点与限制

svelte-i18n：功能完整——运行期 `register()` 异步按语言加载、`fallbackLocale`
恒定加载、`handleMissingMessage` 缺键回调（`warnOnMissingMessages` 已标记废弃）、
`$number/$date/$time` 包装 Intl、`getLocaleFromNavigator()` 探测
（[入门](https://github.com/kaisermann/svelte-i18n/blob/main/docs/Getting%20Started.md)、
[格式化](https://github.com/kaisermann/svelte-i18n/blob/main/docs/Formatting.md)、
[方法](https://github.com/kaisermann/svelte-i18n/blob/main/docs/Methods.md)）。
限制是维护停滞（约 23 个月无提交）与运行期 ICU 解析器的固定体积成本。

paraglide：编译期方案，消息编译为可树摇的 ESM 函数，策略化语言检测
（localStorage、cookie、url、baseLocale、preferredLanguage、globalVariable、
自定义），preferredLanguage 用 navigator.languages；`setLocale` 默认
"执行完整文档导航或重载"，`reload:false` 被文档明确定位为
"完全客户端渲染、无 URL 策略、自持响应式外壳"的逃生舱，且"不重渲染 UI"
（[策略](https://paraglidejs.com/strategy)、
[运行时](https://paraglidejs.com/runtime)）。其 SvelteKit 指南的语言切换示例
同样依赖整页刷新（data-sveltekit-reload，
[指南](https://paraglidejs.com/sveltekit)）。旧适配器 @inlang/paraglide-sveltekit
已被 npm 标记弃用（元数据最后更新 2025-03-19），弃用消息指向
@inlang/paraglide-js v2+（[npm 页面](https://www.npmjs.com/package/@inlang/paraglide-sveltekit)）。
官网自称 "SvelteKit's official i18n integration"，这是厂商表述；
svelte.dev 官方文档截至检索日未推荐特定 i18n 库（未核实到推荐页，仅见
[Svelte 官方博客 2023-12 提及社区演讲](https://svelte.dev/blog/whats-new-in-svelte-december-2023)）。
本项目无 SSR、无 URL 路由，其策略与树摇收益主要针对多语言大型目录场景。

typesafe-i18n：CLI 代码生成全类型化目录；无内建基础语言回退（FAQ 明确
不推荐用基础语言兜底，靠类型在开发期拦截缺失）；无 ICU MessageFormat；
README 的 Svelte 示例使用 Svelte 4 语法（export let / store）
（[仓库](https://github.com/codingcommons/typesafe-i18n)）。恢复维护后的
发布节奏与 Svelte 5 适配计划未核实。引入它意味着新增 codegen 构建步骤。

@lokalise/i18n-ai：npm registry 404，包不存在（检索 2026-09-25）。
Lokalise 的 AI 翻译是其翻译管理平台（TMS）功能，不是前端运行时 i18n 库；
本项目也不接入远端翻译或 TMS 服务（[范围合同](README.md)），故不采纳。

自行实现 + Intl：Intl 是 ECMA-402 标准命名空间，浏览器 Baseline
（2017 年起广泛可用），含 NumberFormat、DateTimeFormat、PluralRules、
RelativeTimeFormat、ListFormat、Locale、DisplayNames 等构造器，零 JS 依赖
（[MDN Intl](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl)）。
Intl.MessageFormat 不在 MDN 构造器清单中，浏览器稳定发布状态未核实；
如需完整 ICU 语法须另引库（本合同不引入）。复数需求经 CLDR 核对：
zh 所有基数/序数/区间均为单一 other 类别；en 基数为 one/other 两类、
序数四类（[CLDR 47 复数规则](https://unicode.org/cldr/charts/47/supplemental/language_plural_rules.html)）。
即 zh-CN + en 语言集合下，复数规则只有 en 的 one/other 一种分支。
Svelte 5 `$state` 声明响应式状态，"UI reacts when it changes"
（[官方文档](https://svelte.dev/docs/svelte/$state)），消息查询经 `$derived`
即可获得即时切换，无需第三方运行时。

### Tauri 与图表

Tauri 官方插件列表（2026-09-25 检索）没有 i18n/国际化插件
（[插件索引](https://v2.tauri.app/plugin/)）。crates.io 存在社区
[tauri-plugin-i18n](https://crates.io/crates/tauri-plugin-i18n)
（v2.0.2，2026-02-24 更新，累计下载 3,992，基于 rust_i18n），规模小，不作为依据。

系统语言获取：前端 `navigator.language` / `navigator.languages`（BCP 47，
返回浏览器首选语言，MDN 定义"usually the language of the browser UI"
（[MDN](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/language)））。
本项目三平台 WebView（WebView2/WKWebView/WebKitGTK）均为浏览器内核，
该 API 与 Intl 数据内建可用。navigator.language 与 Windows 系统/WebView2
语言设置的具体对应关系未实测，留 M6 固定样本核验。

切换语言不需要重启应用或 WebView：语言状态在前端，切换是前端状态更新。
若采用 paraglide 默认行为则是整页重载（Tauri 下可行，但重置内存状态）；
自实现与 svelte-i18n 均为即时更新。

ECharts：`echarts.init` 接受 locale 参数，内置 'ZH' 与 'EN' 两个 locale，
其他语言需 `echarts.registerLocale` 且在 init 前调用
（[API 文档](https://echarts.apache.org/en/api.html)、
[5.4.0 说明](https://echarts.apache.org/handbook/en/basics/release-note/5-4-0)）。
locale 在实例 init 时固定；切换语言需 dispose 后按新 locale 重建实例，
该行为依据 API 语义推断，M6 实测确认。内置文案仅覆盖工具栏、时间轴等
少量 UI 文本，坐标轴与图例文案由应用传入，走消息目录。
建议语言集合 zh-CN/en 恰好落在内置 ZH/EN 上，无需额外 locale 文件。

## 选型建议

首选：自行实现轻量消息目录 + Intl 格式化 + Svelte 5 runes 即时切换。
理由：

1. 语言集合预计仅 2 种，复数分支只有 en 的 one/other（CLDR 证据见上），
   不需要运行期 ICU 解析器；
2. 本项目是桌面 SPA，无 SSR、无 URL 路由，第三方方案的主要收益
   （路由策略、SSR 中间件、大型多语言目录树摇）不适用；
3. 资源预算敏感（gzip ≤ 1 MiB 还要容纳 ECharts），零第三方运行时成本最低、
   可测量；
4. 规避第三方维护与 Svelte 5 兼容风险：svelte-i18n 停滞约 23 个月，
   typesafe-i18n 的 Svelte 5 适配未落地（#778 开放）；
5. 诊断消息不翻译（见合同），进一步缩小目录规模与第三方能力需求。

代价：键类型检查、缺键诊断与两目录键集合一致性校验需自建。
目录规模小（预计数百键），用校验脚本 + 测试覆盖，工作量有界。

升级路径：若语言集合扩展到 3 种以上、引入译者工作流或需要完整 ICU 语法，
优先重新评估 paraglide（维护活跃、编译期类型安全、Vite 插件成熟），
届时按本文维度重新核验版本与切换行为。

未采纳原因：svelte-i18n——维护停滞，运行期解析器体积对 2 语言场景是纯开销；
typesafe-i18n——Svelte 5 适配未落地，codegen 增加构建链；@lokalise/i18n-ai——
包不存在，且 TMS/AI 翻译依赖远端服务，违反本项目不接远端服务的边界。

## 本项目 i18n 合同

以下为当前实施合同；上文两语言方案比较是 2026-09-25 的历史决策依据。

1. 语言集合：zh-CN（默认）、zh-TW、en、ja、ko、es、fr、de、pt-BR、ru。
   设置页使用各语言的本地名称，保存后立即切换。新增键须同步全部目录。
2. 语言协商顺序：用户设置（持久化保存）→ 系统语言 → 默认语言 zh-CN。
   只有已保存语言无效或缺失时才读取 navigator.languages。zh-Hant/TW/HK/MO
   归入 zh-TW，其余 zh 归入 zh-CN；en/ja/ko/es/fr/de/pt/ru 取已支持的
   语言目录，pt 归入 pt-BR；均未匹配时回默认。
3. 缺失键回退：界面文案键在当前语言缺失时，显示默认语言（zh-CN）的同一键文案；
   默认语言也缺失属开发缺陷，运行时告警并显示键名。测试检查 10 份目录
   的 292 个键、非空值及所有插值参数一致，不接受发布时的静默缺译。
4. 键名规范与语言包组织：扁平键、小写点分命名空间，`页面.区块.条目`，
   如 overview.today、settings.timezone；插值用单层花括号 {name}；文案
   不内嵌 HTML。新增语言使用同一有序键表，长度和键集合由测试检查。
   目前不使用复数变体或 ICU 语法；新需求出现时再按语言规则设计。
5. 格式化口径：数字、千分位、小数位、百分比、日期时间统一用 Intl
   （Intl.NumberFormat/DateTimeFormat，ECMA-402，WebView 内建、零依赖），
   locale 取当前界面语言；相对时间使用 Intl.RelativeTimeFormat，
   zh-CN/zh-TW 的万、亿单位按本地文字显示，其余语言使用 Intl 紧凑数字。
   单位词（token、次、天）作为目录文案拼接，不做单位换算。
   统计口径不随语言隐式改变：时区、周起始、区间定义、去重规则、单位含义
   是用户设置与 [数据合同](data-contract.md)，查询参数与界面 locale 解耦；
   翻译不得改变任何数值、区间或覆盖范围。
   导出与界面分列：界面显示随语言本地化；CSV/JSON 导出默认输出未本地化
   原始值（ISO 8601 日期、原始数值、稳定英文列头），导出对话框注明
   "导出格式与界面显示格式分列"，避免区域格式差异破坏可回导与对照。
6. 诊断消息与后端边界：采纳"诊断 code 为稳定英文标识、诊断 message 不翻译"。
   评估结论：该立场合理。诊断是白名单枚举加技术事实（字段名、错误码、位置），
   data-contract 已限定 diagnostics 只存脱敏错误、不存原始文本；翻译 message
   会破坏界面展示与验证记录、日志的可对照性，翻译缺失还可能让用户误解
   覆盖范围。需要面向普通用户解释时，由前端按 code 做展示层映射，
   属展示层扩展，不改变诊断本身。后端 Rust 侧：Tauri command 返回结构化
   错误码与参数（与 IPC 结构化 DTO 合同一致），不返回本地化字符串，
   由前端映射到目录键。来源能力声明（CapabilityTable）已是结构化数据
   （Availability 枚举 + note/limitations 自由文本）：结构化部分按语言映射展示；
   note/limitations 原文展示（当前为中文），展示层可后加映射，映射缺失时
   显示原文；翻译缺失不得放宽或收紧能力表述，不得虚构字段能力或覆盖范围。
7. 加载策略：10 份目录随前端打包，未增加第三方 i18n 运行时。
   当前目录只有插值，不需要 ICU 解析器；若包体或启动时间超出
   [资源目标](architecture.md#budgets)，再拆成按语言加载并重新测量。
8. 切换行为：设置保存后即时生效，无需重启。图表标签由应用传入并随语言
   重绘；当前未使用 ECharts 内置工具栏文案，实例内部的 ZH/EN locale
   不会随切换重建。若增加内置工具栏，需要注册相应语言并重建图表。
   后端不感知 locale：
   IPC 数据均为结构化数值与错误码，不含本地化字符串。用户语言设置持久化，
   下次启动按协商顺序恢复；切换语言不触发重新采集、不改变任何统计结果。

## 风险与限制

- 第三方库兼容：本方案不引入第三方 i18n 运行时，规避 Svelte 5 兼容风险；
  若未来改用 paraglide 或其他库，须按本文维度重新核验当时版本与切换行为。
- ECharts 内置文案仅 ZH/EN，实例内部 locale 在 init 时固定；当前图表
  文案由应用传入并随状态重绘。未来若启用内置工具栏，须单独注册 locale 并验收。
- 三平台 WebView 的 Intl/CLDR 数据输出差异未验证；浏览器已验证日语、
  西班牙语即时切换及 10 种语言保存，macOS/Linux 仍以 CI 证据为界。
- navigator.language 与 Windows 系统/WebView2 语言设置的对应关系未实测；
  运行中应用不自动跟随系统语言变化，需重启或重新进入设置页触发协商。
- 10 种语言的文本长度可能造成局部布局溢出；浏览器窄屏检查已覆盖，
  原生 GUI 的逐语言人工审校仍待桌面验收。
- Intl.MessageFormat 浏览器发布状态未核实；本合同不依赖它，若后续需要
  完整 ICU 语法再评估引入库或升级 paraglide。
- 目录完整性由前端纯逻辑测试检查；文字准确性仍需母语审校，
  尤其是清理、导入和导出等有操作后果的文案。
- 上文第三方包体数字均为历史调研资料；本仓库实际构建结果见本轮验证记录。
