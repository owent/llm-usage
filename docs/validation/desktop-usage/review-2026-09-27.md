## 修复合同与结果

归档与活动会话属于同一来源实例。只读有格式证据的本地载体，以原生身份去重，
不以相近时间或相同 token 猜测关联。未知字段保留未知；消息、请求、累计值和额度分别处理。
模型和 Agent 分组、筛选忽略大小写；事件身份不变，不因显示名称变化重复入库。

### ZCode：数据库采集与 JSONL 回退

只读核验本机安装产物 resources/glm/zcode.cjs 的 model_usage 写入及清理逻辑，
SHA-256 为 B1DF2EF3E5BD76C4AF3ECB296BC003A10D3F13191A26610BD0BA940FEADAD529。
原生行身份包含 assistantMessage/span/start/attempt 等来源信息；JSONL 网络 requestId
与它不是同一身份，traceId 也会被多个请求共享。相同时间、token 不足以证明同一调用。

数据库按 started_at 清理约 30 天前记录，因此是有限保留的本地历史，不能称为永久归档。
实现行为：

1. 正常采集即发现 db/db.sqlite，不需要手动补历史按钮。
2. 只读一致快照，验证字段和完成状态，以 model_usage.id 作为来源内调用键。
3. 验证成功后按来源/日同时替换事件、日层、小时层，一次事务提交指纹。
   不把 turn_usage 与逐次调用相加。
4. 应用已经保存的较老历史继续保留。数据库 30 天边界日可能不完整，
   已有日层不被残缺快照覆盖，并产生诊断。已超出应用日层保留范围的数据不重新拆日。
5. 来源曾使用数据库后，数据库缺失或损坏则保留统计并报错，不能悄悄改用 JSONL 双计。
   只有从未使用过数据库的来源才走 JSONL 回退。
6. DB 缺少逐条产品版本证据，记录 latest_fallback；有效数值可统计，版本覆盖仍待验证。

只读真实核对命令：cargo run --manifest-path desktop/src-tauri/Cargo.toml

分别存储，未写入真实应用库或 Agent 日志。

ZCode 的旧“不支持”文件缺 `sessionId`，但有 `requestId` 和用量；主数据库
已被设为权威来源，现有采集不再读取 JSONL，以免跨载体双计。只读对照发现
该 JSONL 的请求 ID 与 DB 原生/逻辑请求 ID 均无匹配，且同日时间附近的
token 数也不同；`trace_id` 并非逐调用唯一，因此不能证明数据库已覆盖该调用。
文件名虽像测试样本，但不能据此判定为无效或安全忽略。本轮保留该告警和
原有统计，不把 JSONL 直接相加；来源卡片新增“未识别 1 个文件”，使原因可见。
隔离新库初次扫描 ZCode 为正常，因为 DB 主载体跳过了旁路 JSONL；
此结果只验证 DB 路径可用，不能证明旁路文件的用量已被纳入。

未知版本本来就按 Agent 专属最新内置解析器尝试，结构通过的数据会计入统计，
版本依据仍保留 `latest_fallback`。本轮修复两处跨 Agent 判定：增量扫描继续
使用已保存的版本依据；兼容解析若出现坏记录，即使有有效调用也显示部分数据
需核对，而不是让 `active_compat` 掩盖异常。初次完全不兼容仍拒绝，不能用
“成功 0 条”代替错误。数据源卡片区分兼容读取与降级文件，前者用普通信息色。

补充回归覆盖：未登记版本的有效调用正常入账并保持正常来源状态；同一文件
后续出现无效用量时保留已计入的两个调用、文件及来源标为降级；ZCode 成功
读取主数据库后，旧 `unsupported`/`degraded` JSONL 告警仍保留，不能用

## 逐日热力图与多语言扩展

用户要求热力图每格为一天，并补主要语言。原实现将所选日期范围压成
星期几 × 小时，相隔一周的同一小时被合并；直接读留存事件，在事件清理后
漏掉仍有每日汇总的用量。现按所选 IANA 时区输出连续本地日期，从
daily_usage 汇总每日期的调用和已知 token，并与总览日层使用同一筛选规则。
每日层保留截止线之前、且该日已无匹配日层数据时返回不可用状态；
周期归档本身也单独检查，覆盖没有本机每日截止线的导入库。同日若还有
部分日数据，则保留已知数值并标记部分覆盖。周/月/年物化总量不能按日拆分，
因此不会填零、分摊或重算。周分布直接合并这些日期格，并在覆盖不全时提示边界。
合成测试包含跨周同星期、
上海时区跨 UTC 日期、事件删除后保留日层、大小写筛选、空用户集合、
日层清理后仅有周期归档、无截止线的周期导入、同日部分保留等情形。

界面改用日历格，暗色底格和颜色分级均由主题变量控制，清理后的日期用
斜纹区别于零调用，部分覆盖用虚线框；短范围旁显示已知活跃天数、
已知最长连续活跃与已知最高调用日期，避免覆盖缺口被误读为完整结果。
浏览器深浅主题截图确认没有旧黑块；日期格数量与筛选范围一致。

新增繁体中文、日语、韩语、西班牙语、法语、德语、巴西葡萄牙语和俄语，
与原有简体中文、英语合计 10 种语言。292 个界面键逐语言齐全，
测试核对键集合、非空文案和插值参数；语言选择可持久化且即时生效。
日期、数字、相对时间走当前 locale 的 Intl 格式化，统计时区和查询结果不由
翻译决定。诊断原文和来源原始名称不属于界面翻译。各语言文字仍需母语审校，
尤其是有操作后果的清理、导入和导出说明。
