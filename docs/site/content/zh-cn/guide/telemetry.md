原生历史不一定包含所有 token 字段。受支持客户端可提供补充的本地 OTel file 导出，
或显式认证的本地 HTTP 遥测。各客户端接口和版本都需要独立核对。

## 应用前核对

总览显示紧凑配置摘要；**查看详情**进入设置中的遥测配置面板。检查在后台只读执行，
区分缺配置、已配置等待数据、样本核验和冲突。残留配置目录本身不证明客户端已安装。

可查看单项配置预览，或批量处理已安装、受支持且缺配置的项目。应用按用户层合并字段，
保留已有输出目标及无关设置/注释。冲突项和仅能手工处理的项目分别报告。需要时重载 IDE；
生成的 CLI launcher 必须主动使用，不会自动执行。

## 文件输出与重叠

LLM Usage 关闭后，文件输出仍可继续，之后再采集。它不能恢复启用导出前的请求，
客户端自己的保留规则也可能删除历史文件。

已核验的 VS Code Copilot file span 按主机、用户、会话和本地日替代符合条件的原生贡献。
原始记录仍保留；近似时间或相同 token 不证明调用身份。已停止改写的分区保留已经选择的贡献。
其他导出在格式和重叠独立核验前保持隔离。

## 本地 HTTP 接收器

接收器默认关闭，仅绑定 `127.0.0.1`，支持已核验的 OTLP JSON/protobuf HTTP traces 和 logs，
不支持 gRPC 或 metrics。接收时应用必须运行。

每个配置来源需要独立凭据，存于 OS 凭据库。预览和 IPC 不返回凭据内容。持久安全存储不可用
时拒绝配置，不开放无认证接收器。撤销核对自有凭据删除，并拒绝后续请求。

配置能力不能据此确认真实 exporter。具体客户端版本、输出命名、手工路线、回滚和凭据边界见
[遥测要求](/zh-cn/reference/design/copilot-otel/)和
[接收认证要求](/zh-cn/reference/design/receiver-auth/)。
