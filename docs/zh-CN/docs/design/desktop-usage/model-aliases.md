# 带版本的模型名称映射

本功能让模型显示映射能够独立于价格和应用版本更新。原始模型、供应商、用量、归属、
分组/筛选键及已保存的估算保持原样。保留用户授权的 Qoder `qmodel_latest` →
`Qwen4-Max-Preview` 内置回退。目录名称不证明供应商发生回退后实际提供的模型。

## 来源与刷新

- 内置现有显示覆盖，离线启动也可使用；明确保留其 `user_override` 依据。
- 验证后导入用户选择的本地 JSON 目录。不扫描任意 Agent 文件，不从提问、回答、
  通用日志或已安装版本中提取、推断模型名称。
- 在线刷新独立于费用估算，默认关闭。固定公开来源为
  `https://llm-usage.atframe.work/models/aliases.json`，可回退到同一目录的仓库原始文件
  精确地址。请求不包含账号凭据、用量、来源路径、主机 ID 或查询模型，不调用账号、
  账单或模型生成 API。
- 在 GUI 启动和采集成功后检查过期目录。默认缓存三天，可配置为 1–365 天；手动刷新
  跳过缓存时限。限制 HTTPS 耗时和响应大小，拒绝重定向，只访问两个固定公开地址。
  失败时保留上次有效目录并报告错误，不阻塞采集；离线和手工目录继续可用。

公开目录作为普通文档静态资源随仓库维护，新端点在对应文档部署后才可用。
资源已准备或模拟下载测试通过，不代表公开部署已经完成。
精确回退地址为
`https://raw.githubusercontent.com/owent/llm-usage/main/docs/site/public/models/aliases.json`。
项目维护者核对来源后更新此目录；它不自动识别供应商隐藏的路由，也不是 Qoder 官方的
实时 key 到模型名称 API。

## 目录格式

JSON 使用 `schema_version: 1`、非空 `rule_version`、UTC `published_at` 和有数量上限的
`aliases`。每项包含精确 Agent ID、原始 `key`、可选的精确 `provider_id`、`display_name`、
`effective_from`、可选的不含结束时刻 `effective_until`，以及公开 `source_urls` 和 `basis`。
只允许分隔符和大小写拼写归一；未知命名空间、后缀和版本保持独立。拒绝无效时间、空范围、
控制字符、过长内容、重复规则、未知结构字段和无效区间。错误回复不回显 JSON 正文。

```json
{
  "schema_version": 1,
  "rule_version": "example-2026-11-16",
  "published_at": "2026-11-16T00:00:00Z",
  "aliases": [{
    "agent": "qoder",
    "key": "qmodel_latest",
    "display_name": "Qwen4-Max-Preview",
    "effective_from": "2026-11-16T00:00:00Z",
    "basis": "user_override",
    "source_urls": []
  }]
}
```

依据允许 `user_override`、`catalogue` 和 `native_snapshot`，仅记录声明的依据，
不代表独立认证。单份目录上限为 1 MiB/2,000 条规则，候选历史上限为 20,000 条规则/
4,096 个版本，保存的元数据上限为 32 MiB。超过上限时保留旧状态。

目录只适用于其声明的范围。限定供应商的规则要求记录自身提供该供应商；已安装客户端或
数据库整体版本不能识别其他历史记录。首个格式不认证客户端版本或宿主专用目录；这类范围
需要单独核验并扩展格式，尚不支持的字段直接拒绝，不静默忽略。

## 持久化与冲突

通过现有写入器，在一个事务中将有效候选、最新成功响应原文和哈希保存为应用元数据设置。
不改变数据库结构版本，不重建数据库。网络下载在写入锁之外进行。手工导入、设置变化或
其他进程更新目录后，较旧的后台结果不能覆盖新目录。

保留每个候选及其来源、版本、哈希和有效区间。相同内容重复导入不增加记录；同版本内容
不同则无效。发布时间较早的在线目录不能替换成功缓存。较晚的生效起点从该时刻起接替
旧开放区间，但不改写旧候选。同范围、同起点的不同名称保持冲突，后续下载也不清除。
新规则到期后不能重新启用更早的开放映射。SHA-256 用于标识缓存内容，不是发布者签名；
信任边界是 HTTPS 和仓库所有权。损坏的缓存或状态须报告，不能静默视为已核验数据。

## 查询与界面

优先使用记录自身已保存的 canonical 模型；本次不增加未经核验的原生读取器，也不补填
缺失的 canonical 字段。否则按精确 Agent/供应商和用量/查询时间范围解析。不同供应商和
同名路由保持独立；区间冲突或缺失时保留原始 key。跨不同名称的汇总同样保留原始 key，
不把汇总 token 或调用归属给其中一个模型版本。
精确供应商规则优先于 Agent 通用规则；同范围内使用最近的有效起点。小时汇总名称保守地
要求映射覆盖完整本地日期，包括夏令时重复小时；记录明细使用精确发生时间。

汇总和图表的名称判断与用量采用相同的保留分区、筛选和读取快照。查询加速不能丢失名称
所需的 Agent 范围。汇总缓存键与界面刷新检测包含元数据代次，但不改变用量修订号。
明细使用自身记录时间。筛选项可显示当前目录名称，但值保持原始 key；表格标题保留原始
key。计价和参考模型选择不使用显示映射。

设置提供在线开关、缓存天数、刷新状态、立即刷新和本地目录导入。开启在线元数据不要求
启用费用估算。旧设置反序列化后默认关闭刷新。控件保持多语言支持，自动保存保留草稿，
失败不丢弃有效元数据。
关闭在线刷新即可停止下载。修改映射时，导入带明确有效期的新版本并保留已有候选及用量
数据库。旧版应用可以忽略这项元数据设置，无须迁移数据库结构。

## 必需检查

覆盖解析边界、重复/版本冲突、供应商与 Agent 范围、区间边界和缺口、未来规则、混合汇总
范围、新规则结束后不恢复旧映射、重复导入、缓存损坏、时限和失败回退、事务回滚以及
旧后台结果/跨进程仲裁。不清库验证旧数据库，确认原始导出和价格不变，并检查加速、
日/归档/小时查询及仅元数据更新后的实时界面。模拟 HTTP/IPC、原生可执行文件和公开来源
检查分别记录。临时产物放在根目录 `build/model-aliases-20261116/`。
