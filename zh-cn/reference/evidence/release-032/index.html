0.3.2 兼容读取与遥测文案核验

范围：根据逐版本原生样本修复 Codex/Kilo 兼容提示，改进本地 OTel 说明， 并将应用清单版本更新为 0.3.2。下述本地检查在打 tag 和运行远端 CI 前完成； 后续 tag 构建结果单独记录。原生来源只读提取遵循 脱敏要求。

兼容读取提示

本机应用数据库中有 66 个 Codex 文件和一个 Kilo 数据库标为 active_compat。 提示表示解析器能够识别格式，但记录所属的客户端版本尚未核验，与记录错误分开。 Codex 注册表缺少 0.159.0-alpha.12.1、0.160.0、0.160.1 和 0.162.0-alpha.17.2。 Kilo 有 27 个未登记的会话版本，包含 7.8.3 和 7.8.7。此前 7.8.3 只有空会话， 不能核验用量格式；此次原生会话已有真实调用。

每个新增版本均有独立提取的原生样本和计算的期望值，位于 core crate 的 tests/fixtures/{codex,kilo}/releases-032/：

Codex 版本 调用 含缓存输入 缓存读 含推理输出 推理 总量
0.159.0-alpha.12.1 3 81,454 58,368 756 71 82,210
0.160.0 1 22,600 4,864 203 140 22,803
0.160.1 1 35,556 17,152 138 62 35,694
0.162.0-alpha.17.2 14 392,480 350,720 1,443 345 393,923

Kilo 的 27 个完整原生会话包含 787 次 assistant 调用。新增的精确版本为： 7.3.42、7.3.45、7.3.46、7.3.49、7.3.50、7.3.54、7.3.63； 7.4.1、7.4.2、7.4.5、7.4.7、7.4.11、7.4.13、7.4.15、7.4.16、7.4.17、 7.4.20、7.4.22、7.4.23；7.5.6、7.5.14；7.6.0、7.6.2；7.7.5、7.7.12；7.8.3、7.8.7。 逐版本期望值保留五个互斥桶、派生总量、缺失的原生总量及原生会话快照。 26 个快照一致；7.3.42 明细已有正用量，累计快照却为零。差异继续保留为审计诊断， 不会据此丢弃有效调用，也不会用快照核验版本。

样本进入 Git 前已移除或匿名化正文、路径和身份标识。新增 Kilo 样本将 Provider 标识 替换为常量，保留模型名、时间、token 数值和所属会话版本。样本仅核验原生 CLI/数据库 格式，不扩大 IDE 或遥测支持范围。

compatibility_release_032.rs 使用旧兼容解析依据生成真实的旧事件摘要并消费游标， 随后通过完整内置注册表重新发现来源。检查父目录发现、逐 token 字段、已核验版本依据、 统计和首次观测时间不变、诊断保留、无冲突及重复读取幂等。未知或缺失版本、混合数据库、 空会话及坏记录继续沿用已有检查。登记一个版本不会核验相邻版本。

真实旧数据库核验还发现了文件连续性缺陷：一个稳定的 63,974,896 字节 Codex 文件 反复停在第 33,554,261 字节。库中保存的创建时间指纹与文件当前创建时间不同。 重读保存了文件大小、修改时间和内容指纹，却遗漏新的创建时间，导致每次扫描都重置 文件代数。现已将创建时间与其他指纹、事件和游标在同一事务中保存。独立回归在修复前 只读到一次调用，期望为三次；修复后核对仅重置一次、重开数据库后继续前进、 读完三次调用且源文件字节不变。

创建时间指纹回归覆盖

Issue #1 指出的测试缺口成立： 文件系统未提供创建时间时，codex_file_fairness.rs 在任何断言之前就直接返回。 现已让测试始终执行。有原生创建时间时保留文件重建场景；缺少创建时间时，写入旧创建时间 和不匹配的文件头指纹以触发重扫。重开 SQLite 后检查完整的持久化指纹，包含清除过期创建时间， 以及文件代数恰好增加一次。随后检查三次调用/360 token、重复读取后的指纹和代数稳定， 以及源文件字节不变。产品代码和采集行为没有变化。
