2026-09-27 审查、归档与界面改进

状态：本轮修复和本机验证完成。范围包含 4ef354d42dac2ca9f86ae101f70908ff4cb2f7eb 至 ff1e458，即 4ef354d^..ff1e458 的九个提交、444 个变更文件。初始工作区干净。 核对设计与版本依据、全部改动清单、采集至 UI 的数据流、测试、构建和文档； 历史验证结果不计作本轮通过。未提交、推送、安装或部署。

修复要求与结果

归档与活动会话属于同一来源实例。只读有格式依据的本地记录，以原生身份去重， 不以相近时间或相同 token 猜测关联。未知字段保留未知；消息、请求、累计值和额度分别处理。 模型和 Agent 分组、筛选忽略大小写；事件身份不变，不因显示名称变化重复入库。

审查发现 修复及回归依据
Codex 仅发现 sessions，归档后首次采集遗漏 同时发现 archived_sessions；只有归档、活动与归档副本并存、再次扫描均只计一次
ZCode 时间/token 近似匹配会误合并；迟到 JSONL 会重复 本地 model_usage 原生 ID 为主；按来源/日原子替换，禁止跨格式猜测匹配
历史周期写每个维度前删除整个周期，最后仅余一个维度 每周期只删除一次；多来源、多模型均保留；重复清理结果不变
部分日层覆盖完整周期，汇总与分组取数规则不同 共用层级覆盖选择器；仅使用完全落入查询范围的周期；保留日层截止线
名称大小写在汇总、小时、明细与图表间处理不一致 SQLite 注册与 Rust 一致的小写函数；各路径统一；不同供应商保留独立模型行
小时会话取整日再逐维度相加；跨日会话重复 按筛选范围及来源/会话去重；缺少会话 ID 或只有历史汇总时显示未知
耗时平均值以全部调用作分母 按有耗时的样本加权；新增耗时样本量；未知样本不补零
小时汇总压平字段质量、冲突数；缓存占比混用样本 保留质量与冲突计数；留存明细恢复配对样本规则；旧封存数据不能恢复的字段显示未知
无来源用户的空筛选被当成所有来源 区分未限定与明确空集合，阻止跨用户统计泄漏
导出漏近期未封存日层和历史周期，导入漏字段 直接导出聚合快照，包含日/小时/周期与覆盖计数；保留原始主机；错误导入整体回滚
导入可能覆盖仍有明细的本地分区 相同包重复导入不改变数据；不同内容与活跃明细冲突时明确拒绝，避免封存或覆盖实时来源
原生汇总失败前已提交游标，重试可能漏读 原生汇总、事件、游标共用事务；Hermes 故障注入验证回滚、失败状态与完整重试
间隔 0 仍扫描；并发触发判断存在竞态 0 停止间隔提取；更改间隔及手动完成重置期限；同一刷新原子合并
第二进程打开库可能恢复仍运行的任务 每库 OS 文件锁；headless 请求合并到持锁进程；崩溃自动释放锁
headless 版本不匹配进入删库对话框 无窗口启动直接返回错误并保留库；交互恢复仍由 GUI 明确处理
切回曾使用的时区不含后来采集数据 从留存明细重建目标时区日/小时分区；已清理的历史不猜测换算

ZCode：数据库采集与 JSONL 回退

只读核验本机安装产物 resources/glm/zcode.cjs 的 model_usage 写入及清理逻辑， SHA-256 为 B1DF2EF3E5BD76C4AF3ECB296BC003A10D3F13191A26610BD0BA940FEADAD529。 原生行身份包含 assistantMessage/span/start/attempt 等来源信息；JSONL 网络 requestId 与它不是同一身份，traceId 也会被多个请求共享。相同时间、token 不足以证明同一调用。

数据库按 started_at 清理约 30 天前记录，因此是有限保留的本地历史，不能称为永久归档。 实现行为：

  1. 正常采集即发现 db/db.sqlite，不需要手动补历史按钮。
  2. 只读一致快照，验证字段和完成状态，以 model_usage.id 作为来源内调用键。
  3. 验证成功后按来源/日同时替换事件、日层、小时层，一次事务提交指纹。 不把 turn_usage 与逐次调用相加。
  4. 应用已经保存的较老历史继续保留。数据库 30 天边界日可能不完整， 已有日层不被残缺快照覆盖，并产生诊断。已超出应用日层保留范围的数据不重新拆日。
  5. 来源曾使用数据库后，数据库缺失或损坏则保留统计并报错，不能悄悄改用 JSONL 双计。 只有从未使用过数据库的来源才走 JSONL 回退。
  6. DB 缺少逐条产品版本核验依据，记录 latest_fallback；有效数值可统计，版本覆盖仍待验证。

逐日热力图与多语言扩展

用户要求热力图每格为一天，并补主要语言。原实现将所选日期范围压成 星期几 × 小时，相隔一周的同一小时被合并；直接读留存事件，在事件清理后 漏掉仍有每日汇总的用量。现按所选 IANA 时区输出连续本地日期，从 daily_usage 汇总每日期的调用和已知 token，并与总览日层使用同一筛选规则。 每日层保留截止线之前、且该日已无匹配日层数据时返回不可用状态； 周期归档本身也单独检查，覆盖没有本机每日截止线的导入库。同日若还有 部分日数据，则保留已知数值并标记部分覆盖。周/月/年物化总量不能按日拆分， 因此不会填零、分摊或重算。周分布直接合并这些日期格，并在覆盖不全时提示边界。 合成测试包含跨周同星期、 上海时区跨 UTC 日期、事件删除后保留日层、大小写筛选、空用户集合、 日层清理后仅有周期归档、无截止线的周期导入、同日部分保留等情形。

界面改用日历格，暗色底格和颜色分级均由主题变量控制，清理后的日期用 斜纹区别于零调用，部分覆盖用虚线框；短范围旁显示已知活跃天数、 已知最长连续活跃与已知最高调用日期，避免覆盖缺口被误读为完整结果。 浏览器深浅主题截图确认没有旧黑块；日期格数量与筛选范围一致。

新增繁体中文、日语、韩语、西班牙语、法语、德语、巴西葡萄牙语和俄语， 与原有简体中文、英语合计 10 种语言。292 个界面键逐语言齐全， 测试核对键集合、非空文案和插值参数；语言选择可持久化且即时生效。 日期、数字、相对时间走当前 locale 的 Intl 格式化，统计时区和查询结果不由 翻译决定。诊断原文和来源原始名称不属于界面翻译。各语言文字仍需母语审校， 尤其是有操作后果的清理、导入和导出说明。

本节验证环境为 Windows x64、Node.js 24.21.0、Rust 1.98.1； 浏览器使用合成 IPC，不能代替原生 GUI 或真实日层清理后的安装验收。
