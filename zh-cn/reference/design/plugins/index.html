用户安装的桌面插件

本文为待评审的设计提案。工程依据是 2026-11-20 核对的桌面版 0.3.13，提交为 4c016d68b643。 拟支持从本地安装插件包，逐项启用插件提供的功能，并在设置页配置。实施顺序和验收条件见执行计划。

现有实现与接入位置

范围 源码已有行为 对设计的影响
采集 Rust 注册表构造 41 个内置适配器。桌面扫描器在手动和后台采集时使用同一注册表，两个解析槽共享一个写入端。框架在同一事务提交事件、累计记录和游标。注册表、扫描器、适配器框架 沿用同一条发现与入库路径。内部 trait 返回静态 ID，接收文件路径，归档接口还可以访问存储。公开接口需要支持运行时 ID，并缩小可见输入。
模型信息 核心将有生效日期的名称候选和缓存存入同一个设置项。版本表以规则版本为键，读取持久化状态时识别手动和在线两种来源。桌面刷新逻辑认识同一份目录的两个 URL。核心、刷新 各数据源需要独立的标识、缓存和版本历史。上下文窗口、输入输出模态等属性也需要独立字段和出处，单个显示名无法表达这些信息。
价格 内置快照、手动导入和可选的 models.dev 下载共用价格引擎。现有来源类型为 manual、seed、community。非手动快照省略 official_vendor 时，该字段默认为真。解析与选价、存储、刷新 插件价格应有独立的来源与优先级。直接沿用社区快照或手动导入流程，会把原来赋予这些入口的信任交给第三方。
导出 设置页和类型化 IPC 枚举 summary-csv、exchange、details。CSV 使用汇总查询，交换包分支按用户和主机选取来源实例，另行确定历史范围。前端传入所选文件的父目录，后端生成文件名。设置页、IPC、导出命令 自定义格式声明数据集与筛选项。预览显示实际写出范围，并把任务绑定到用户选定的具体文件。

插件包与运行时选型

每个包都使用版本化清单。只提供宿主已定义的模型信息或价格时，包内放数据即可。 需要新增 Agent 解析逻辑、转换其他目录格式或编写导出编码器时，可以提供 WebAssembly 组件。 使用 WebAssembly 接口类型语言 WIT 描述输入、输出与资源句柄。公开 SDK 独立于应用内部 Rust trait、Serde 结构、SQLite 表和 Tauri 命令。

备选方案 本项目的取舍
清单和结构化数据 优先交付给模型与价格数据源。可离线安装和校验。复杂的增量解析与自定义编码还需要执行逻辑。
由宿主管理工作进程，运行 WIT 组件 可执行扩展的首选方案。每项功能的每次操作创建独立实例。按需启动进程，普通启动和内置采集无须加载引擎。Wasmtime 是待实测的候选。
原生动态库、Tauri Rust 插件、用户提供的可执行文件或 Node/Python 脚本 适用于随产品一起评审和发布的代码。直接安装原生扩展会赋予其进程用户的权限。单独进程可隔离崩溃，权限仍须额外约束。随包分发其他语言运行时还会改变安装包。
WebView 扩展 主窗口可以调用有权限的应用命令，加载第三方界面会扩大插件权限，无窗口扫描还要另走一条路径。插件声明设置字段，由现有 UI 渲染。

Tauri 文档描述了 Rust crate 插件和按窗口、WebView 授权的方式。WIT 定义导入、导出与资源句柄。 Wasmtime 提供了不同语言实现插件的示例。这些资料支持接口选型，本应用的包体积和平台兼容性还需实测。 Tauri 插件、Tauri 权限、 WIT 参考、Wasmtime 插件示例。

安装、授权与兼容性

  • 本地归档包包含 UTF-8 清单、已声明的数据文件和可选组件。清单记录包格式、带命名空间的插件 ID、发布者、包版本、宿主 API 兼容范围、 功能 ID 与类型、入口路径与 SHA-256、所需输入、设置字段和许可证。分别管理包版本、接口版本、解析规则与游标版本、原生 Agent 版本和数据源修订。 每项功能指定接口主版本和所需特性。宿主同时核验清单和组件实际的导入导出，授权前拒绝无法满足的要求。 用旧 v1 包回归后续 v1 宿主，破坏兼容性的变更启用新主版本。
  • 设置页预览身份、版本、出处、申请的目录和字段、确切的数据源 URL 及导出数据集。安装后默认禁用。用户可以明确启用标为“发布者未验证”的个人未签名包。 摘要标识内容，已验证发布者标识需要绑定受信任密钥的签名。保留内置 ID。更新时核对可信密钥，手动替换本地包则需要明确确认。首版采用本地安装、手动更新。
  • 激活前校验整包，限制压缩及展开体积、条目数量和深度。拒绝越界路径、链接、重复或在目标平台等价的名称、未知的必需接口、未声明文件及不兼容版本。 按摘要加载经过验证的不可变内容。更新时先暂存，确认新设置、授权和解析状态兼容后再替换可用版本。新增权限须重新授权。 重装相同内容是幂等操作，同一 ID 和版本下内容变动须另发新版本。
  • 在应用数据目录内保存活动包摘要、已启用的功能、授权、类型化设置值及配置代次。通过一个宿主事务切换活动引用，崩溃后可恢复旧版或已验证的新版。 更新、禁用或卸载使在途任务失效，事务提交或发布文件时再次核对代次和授权。保留已采集用量、游标、候选、诊断历史和原始估算。后续查询排除已禁用的数据源。 回滚时采用兼容游标，或按现有身份从原始输入重放。原件缺失时显示覆盖限制。
  • 不自动执行目录中的文件，不运行安装脚本，不接收插件渲染的 HTML。设置支持有界文本、枚举、数值和宿主选择器。 涉及真实凭据的集成需要独立设计。真实路径、系统句柄和用户选择均由宿主管理。

执行与资源限制

为各类可执行扩展分别定义 WIT world，只链接该接口允许的宿主函数。默认不提供 WASI 文件系统、网络、环境变量、进程 API、应用数据库或继承的标准输入输出。 工作进程使用宿主专用通道传输有大小限制的消息。句柄绑定到包摘要、具体功能、授权代次和本次操作，任务结束即失效。 同一包的不同功能也不能共享活动实例、句柄、临时存储，或由插件选择并发起网络请求。

宿主限制模块编译、组件内存、表与实例数量、输入输出字节、行数、调用次数和总耗时。限制组件计算量，单独取消宿主 I/O，超时仍运行时终止工作进程。 IPC 帧在分配内存前校验长度。执行插件时释放写锁。仅记录预定义错误码和计数，排除原始内容、插件自由文本日志和含输入的崩溃转储。 Wasmtime 将组件资源和宿主分配的内存分开计算，并提供 fuel 和 epoch 中断机制。需要实测整个进程的峰值和宿主调用超时。 安全模型、资源限制、 执行中断。

Agent 采集

用户为采集器指定本地根目录。插件声明相对发现规则、预期格式和所需字段。 宿主限制在授权范围内枚举并检查实际打开的文件身份，处理链接、Windows 重解析点及路径别名。 首版宿主提供有界 JSON/JSONL 记录读取，以及按已声明表和列投影、按类型化键分页的 SQLite 读取。 宿主划分完整记录、提取所需原生字段，并使用校验过的标识符和绑定参数生成查询。插件无法获取 SQLite 连接或提交任意 SQL。 其他传输格式需独立评审。认领文件前先核对原生结构及本地 Agent 归属。后缀匹配、云端副本或空会话均不能证明支持。

保留内置注册表，在同一扫描器中为启用的插件加入宿主适配层。使用有所有权或可借用的运行时 ID，避免永久泄漏字符串。 保留所有内置 ID 和来源键。新增适配器和格式 ID 按插件及功能划分命名空间，独立于包版本。已有有效归属的文件继续归原采集器。 新文件优先采用已验证匹配的内置适配器。两个插件同时匹配时暂停该文件入库，列出候选供用户选择。 写事务内再次核对归属。覆盖手动文件、提升到父目录发现、无窗口扫描和两个解析槽之间的并发。

每个原生版本分别记录字段出处、未知值和默认零、token 包含关系、记录类型以及稳定原生身份。 例如，一次失败调用可以计为一次，同时保留未知 token。会话累计量不能拆成逐模型调用。 区分用量观测、调用、累计值和额度。只有额度的结果走宿主额度接口，保留原生单位与采样时间。 宿主对照已提供的完整数据页检查 ID 长度、数值范围、覆盖和游标推进，依据已批准的身份规则生成键。 包摘要、解析器版本和每条记录的原生依据用于溯源，排除在稳定去重键之外。 确需原生文本时只提供获准的已声明字段，只持久化统计字段。来源不明的插件即便返回合理数值，准确性仍须用原生数据核对。

获准写入的观测、累计值、适用的额度记录、文件指纹与代次、游标及派生汇总同事务提交。遇到未完整写入的末尾，从最后一个完整边界恢复。 组件异常、校验失败或事务失败时，保留上次已提交的位置供重试。授权撤销后停止任务，直到用户再次授权。遵守暂停、取消及现有双槽调度。 解析规则变更时按需重读已消费且未变化的输入，比对完整旧摘要，保留冲突和封存分区。只有宿主可以授权修正旧记录。 数据规则、调度、文件归属路由。

模型属性与价格

宿主可以打开用户选定的数据文件，也可以为各个已启用的数据源独立获取公开目录。每个源的在线刷新都需单独开启。 授权前显示确切的固定 HTTPS URL。宿主发起有大小和耗时限制的 GET，不带凭据、本地用量、按本机观测到的模型名拼出的查询参数、插件请求头或请求体。 拒绝重定向和非公网目的地址，连接时校验解析结果，请求与本地用量事件无关。原有内置 URL 约束继续独立生效。 按插件、功能和已批准来源分别缓存，记录获取时间、原始内容摘要、来源修订及上次有效内容。沿用默认三天、可设 1–365 天的缓存周期。 下载和解析在写锁外进行，事务内核对设置、代次及活动摘要。单个数据源失败时保留其上次有效数据并独立报错。 手动刷新可以立即执行，后台请求按缓存到期时间安排，与本机用过哪些模型无关。

  • 模型属性。 以精确的提供方和模型、适用 Agent 范围、生效区间与来源修订标识目录条目。 可选字段包括显示名、以 token 为单位的上下文窗口、最大输出 token 和支持的模态。模型详情显示字段、来源和日期，未提供即为未知。 原始用量、筛选及导出键、价格匹配独立于这些属性。保留既有原生、内置和手动名称映射规则。 插件只补充适用范围内缺失的字段。高优先级来源的冲突继续显示。同级声明冲突时保留双方候选，该字段为未知，名称显示原始键。 声明的上下文长度变化不改变观测用量，也不能用来推断实际计价档位。模型映射规则。
  • 费率。 快照及价格行 ID 按来源划分命名空间。记录提供方及模型、区域及渠道、币种、服务档、阈值、单位、各项费率、生效日期及出处 URL。 校验整数缩放、引擎支持的单位与币种，缺失分项保留未知。 对同样适用的精确费率，由宿主为插件分配独立优先级，排在手动、内置种子和内置社区来源之后。 同范围、同优先级的不同源冲突时保持未定价，新修订只取代本源先前适用的版本。 禁止自行声明 official_vendor、高优先级来源或跨模型替代关系。启用的插件可以为精确配置的渠道提供价格，其报价不进入官方供应商回退。 保留既有区域、优先级、渠道与币种、分档及官方回退规则。刷新可以更新当前参考价，已保存的发生时估算保留原价格 ID 和金额。 估算仍默认关闭。定价规则。
  • 迁移。 将既有目录来源、版本历史和成功缓存映射到对应的原有身份，保留价格 ID、优先级及历史估算。 同一来源和版本出现不同内容时记录冲突，不同来源可使用相同版本字符串。根据元数据代次更新展示缓存。 添加第二个来源或移除第一个来源都应保留两者的历史。

额外的数据导出

用户启用导出插件，建立有名称的预设，选择字段和筛选条件，预览覆盖范围，再选定本地文件。 例如，按日导出的 JSON Lines 预设可以只包含选定用户和时间范围内的日期、原始模型、已知输入和已知输出。缺失输出编码为 null。 规范化明细需要独立授权。网络目的地和定时投递会改变数据披露与重试语义，超出首版设计范围。

插件声明支持的数据集（汇总或规范化明细）、必需及可选字段、格式、扩展名及有界选项。宿主取声明、授权和预设三者的交集。 缺少必需字段或无法支持筛选条件时，在写出前明确报错。预览和导出固定日期与时区、用户、主机、来源、模型、保留范围及数据修订，预览过期后重新核对。 在同一读取快照中按稳定顺序分页。对明细和已封存汇总分区采用现有规则，明确未知值、覆盖和金额币种。 两个数据集都排除原始对话、路径、凭据、插件私有状态与采集游标。交换规则、SQLite 快照隔离。

为目标文件签发一次性输出句柄。后端在同目录写临时文件，编码结束、授权及覆盖确认再次核对成功后，才发布到所选文件名。 取消、磁盘写满、崩溃或失败时清理本任务的临时文件。校验链接，防止把应用数据或采集原件作为目标。 对面向电子表格的分隔文本提供宿主单元格写入接口，负责引号转义和公式防护。自定义产物视为不受信任的数据，不执行也不自动打开。 内置交换格式继续使用各自的大小限制与导入识别。生成报告成功并不代表可以回导。

本地模型名称包

首个实现支持每包提供一项离线 model_aliases 功能。在 设置 → 模型映射 → 模型名称插件 选择本地 .tar.zst 文件。预览插件 ID、版本、发布者、许可证、规则数量和摘要后，选择 安装并保持禁用。 启用一个版本即可应用其名称规则。启用同一插件的另一个已安装版本会切换当前版本。 禁用或移除会撤销相应的名称规则。移除后目录保留在停用的历史记录中，内容相同的包可以重新安装。 清单和目录的历史记录合计上限为 32 MiB。

插件开发指南提供完整目录示例、打包命令、安装与更新步骤以及排错方法。 归档根目录恰好包含两个普通文件 manifest.json 和 aliases.json。 后者使用别名目录格式，每条规则的依据为 catalogue。

使用带命名空间的小写 ID 和 SemVer 包版本。清单摘要按原始字节计算，覆盖清单内的资源摘要。 以相同文件重新打包可以幂等安装，修改任一文件都要更新包版本。应用校验资源摘要，并限制压缩包为 2 MiB、 清单为 16 KiB、别名目录为 1 MiB 和 2,000 条规则。额外文件或链接条目会被拒绝。 这些本地包未签名，界面标明发布者未经验证。

宿主在 v11 SQLite 的新增表中保存已校验的清单和目录。数据库旁的授权文件为每个插件 ID 选择一个摘要。 仅备份数据库时，已安装的包会保留，启用则需要匹配的本机授权。当前实现中，适用的内置、手动及在线导入规则从其首次生效起优先。 选中范围内各插件名称必须一致，冲突时保留原始名称。别名只影响展示。

交付取舍

先支持纯数据包，在 Windows 实测可执行宿主后再定稿 SDK。 首个覆盖完整需求的版本应能通过正常应用入口接入一种新本地 Agent、一份额外的模型及价格来源，并完成一次由用户配置的导出。 逐项记录所依据的源码与原生样本。运行时选型、包体积、性能、SDK 兼容性和原生行为均待执行计划中的实测与发布检查。
